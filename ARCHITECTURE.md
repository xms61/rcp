# Architecture

RCP is one [TanStack Start](https://tanstack.com/start) app (React, TypeScript) served by one Node process, on the owner's PC for now. Pages render on the server and hydrate in the browser. Recipes will live in one SQLite file, reached through Drizzle ORM, and nutrition is computed from each recipe's ingredients ([design doc](docs/design-docs/nutrition-from-ingredients.md)). Why these choices: the bootstrap plan's [decision log](docs/exec-plans/active/bootstrap.md#decision-log).

## Code map
| Path | Holds |
| :-- | :-- |
| `src/routes/` | Pages, one file per route, named by TanStack Router's file-based routing. `__root.tsx` is the HTML shell around every page |
| `src/routeTree.gen.ts` | The route tree, generated by the TanStack Router plugin on `pnpm dev` and `pnpm build`. Committed, because typecheck and lint need its types; never edited by hand |
| `src/router.tsx` | Creates the router; TanStack Start calls its `getRouter()` |
| `src/domain/` | Recipe logic in plain TypeScript, such as converting amounts to grams |
| `scripts/` | Repo tooling: the doc and tracked-file checks, the agent guard hook, setup |
| `docs/` | The system of record ([KNOWLEDGE_BASE.md](docs/KNOWLEDGE_BASE.md)) |

## Layers
`routes → server → db → domain`: a layer may import the layers to its right, never to its left.
- `src/domain/`: plain TypeScript. No React, TanStack, Node APIs or I/O, so it runs anywhere and its tests need no setup.
- `src/db/`: the Drizzle schema and queries. Not created yet; it comes with the first feature that stores recipes.
- `src/server/`: TanStack Start server functions, the only way pages reach the database. Not created yet either.
- `src/routes/`: pages, which call server functions and may use `domain` to format values.

ESLint enforces the `domain` boundary (`no-restricted-imports` in [eslint.config.js](eslint.config.js)). When `db` and `server` are created, extend the rule to them in the same change.

## Invariants
- `src/domain/` imports nothing from React, TanStack, Node or another `src/` layer: ESLint, `no-restricted-imports`.
- No test is skipped or focused in committed code: ESLint, `vitest/no-disabled-tests` and `vitest/no-focused-tests`.
