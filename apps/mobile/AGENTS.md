# apps/mobile: the Android app

The Expo app (SDK 57, React Native, Expo Router) that runs on the owner's Android phone and talks to `apps/api` over HTTPS ([design doc](../../docs/design-docs/mobile-app-and-api.md)). The root [AGENTS.md](../../AGENTS.md) still applies; this file adds what is specific to the app. Claude Code reads it through [CLAUDE.md](CLAUDE.md), which imports it, since Claude Code loads nested `CLAUDE.md` files but not `AGENTS.md`. Adapted from the notes in Expo's blank-typescript template.

## Expo changes every SDK
APIs you remember may be renamed, moved or removed. Before writing code that touches an Expo or React Native API, read the major version of `expo` in `package.json` and the matching docs at `https://docs.expo.dev/versions/v<major>.0.0/`, or start from https://docs.expo.dev/llms.txt. The same holds for React Native Testing Library 14: its `render`, `fireEvent` and `userEvent` calls are async, and its own guide ships in `node_modules/@testing-library/react-native/docs/guides/llm-guidelines.md`.

## Commands (from the repo root)
| Task | Command |
| :-- | :-- |
| Add a package | `pnpm --filter @rcp/mobile exec expo install <package>`, which picks the version matching the SDK. Ask first (root AGENTS.md). If pnpm then adds `minimumReleaseAgeExclude` to `pnpm-workspace.yaml`, undo it and loosen the range instead ([CODE_STYLE.md](../../docs/CODE_STYLE.md#stack)) |
| Develop | `pnpm --filter @rcp/mobile start`, then scan the QR code with Expo Go on the phone |
| Tests | `pnpm --filter @rcp/mobile test` (jest-expo with React Native Testing Library) |
| Typecheck | `pnpm --filter @rcp/mobile typecheck` |
| Build and install the APK | `pnpm --filter @rcp/mobile android` (`expo run:android --variant release`), which needs Android Studio with JDK 17 and the Android SDK on the PC. Only a release build runs on its own and refuses `http://` addresses; a debug build loads its code from the PC and allows http |
| Development build | `pnpm --filter @rcp/mobile android:dev` (`expo run:android`), for a library Expo Go lacks |

## Rules
- Screens live in `src/app/`, one file per route, and `_layout.tsx` files define navigators. Other code, such as `src/connection/`, stays outside `src/app/`, and screens take their dependencies as props so tests can pass fakes.
- `android/` is generated by `expo prebuild` or `expo run:android` and git ignores it. Configure native behavior in `app.json` and config plugins, never by editing `android/`.
- Expo Go has only its bundled native modules. A library with its own native code needs a development build (`android:dev`).
- The token is kept only with `expo-secure-store`, and `app.json` keeps `android.allowBackup` false (docs/SECURITY.md). Anything in `app.json` or an `EXPO_PUBLIC_*` variable ships inside the APK, so it is public.
- Builds happen on the owner's PC with Gradle; EAS cloud builds were turned down (migration plan, Decision log).
